# 查寝监测 WebUI

在网页完成学校账号、OneBot 群通知、刷新计划及月度网费提醒配置。单容器、零第三方 Python 依赖；本项目不接入收费服务或会员付费功能。

“查寝记录”下方新增宿舍电量：手动查询、自动查询开关、独立分钟间隔（默认 60，范围 5–10080）。复用学校账号，默认西校区 26 号北楼 8 楼 814；独立脚本用法见 [ELECTRICITY.md](ELECTRICITY.md)。本轮电量功能未加入 Docker 镜像，交由 Gemini 补齐镜像文件后部署。完整新版可先执行 `python webui.py` 在本地运行。

## 启动

在本目录执行：

```powershell
docker compose up -d --build
```

然后打开 **[http://127.0.0.1:8787](http://127.0.0.1:8787)**。

1. 首次打开网页，设置至少 10 个字符的管理密码。
2. 填写学校学号和登录密码，点击「保存配置」。
3. 点击「手动采集」验证账号。此操作不会推送，也不会将新记录标为已读。
4. 设定刷新间隔，点击「保存配置」，再点击「启动监测」。

无需配置学校或 QQ 环境变量，也无需修改代码或 `.env`。默认关闭查寝推送和网费提醒；没有机器人时可以只监测学校数据。

## 免费 OneBot 通道与强制 @全体

所有发送到普通 QQ 群的通知（查寝、网费及人工确认后的网费重试）均使用原生 @全体消息段，不使用普通文字冒充，也不在权限不足时降级。

你需要另外运行一个免费、开源且已登录 QQ 的 OneBot 11 HTTP 服务，并让该 QQ 账号拥有目标群的 @全体权限与额度。本项目提供接入，不内置 QQ 登录客户端；无需购买短信、云通知或会员服务。没有可用 OneBot 服务时，网页仍可配置和预览，真实群通知不会发送。

网页的「群通知」填写：

1. **OneBot HTTP 地址**：Docker Desktop 访问本机服务可填 `http://host.docker.internal:3000`，端口以你的 OneBot 设置为准。容器中的 `127.0.0.1` 指向容器自身。Linux 上可使用同一 Docker 网络的 OneBot 服务名或可达的主机地址。
2. **Access Token**：填写 OneBot 已设置的令牌，不回显，留空保持原值；若该服务未设置令牌可以不填。
3. **目标 QQ 群号**：填写普通群号，不是 `group_openid`。
4. 保存后点击「检查连接和 @全体权限」。该按钮只检查，不发消息。服务需支持 `get_group_at_all_remain` 扩展，发送前也会检查权限与额度。

官方 QQ 群聊通道不能满足本项目的强制 @全体要求，网页保留其凭据管理但不用于发送；旧 CLI 的官方群发送也已禁止。官方文档说明 [@全部成员仅文字子频道可用](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/text-chain.html)。OneBot 的原生消息段规则见 [协议文档](https://github.com/botuniverse/onebot-11/blob/master/message/segment.md#某人)，额度检查扩展见 [实现方文档](https://docs.go-cqhttp.org/api/#获取群-全体成员-剩余次数)。

## 每月网费提醒

在网页「每月网费提醒」设置开关、每月 1–31 日、北京时间、缴费人数和每人金额（最多两位小数）。总额在页面实时计算，服务端以 Decimal 精确计算；例如 6 人 × 18.88 元 = 113.28 元。

通知包含月份、人数、每人金额、总额，以及“请大家前往微信宿舍群转账”的说明和备注要求。它只发送提醒，不执行微信转账或收款。

- 与查寝启停及查寝推送开关独立：学校监测停止时，已开启的网费提醒仍然运行。
- 日期不足的月份按当月最后一天发送；开启时若已过本月计划时间，会补发本月一次，不补发以前月份。
- 同一目标群每月成功发送一次。修改金额、日期或重启容器后，不重复发送已成功的月份；不同目标群独立记账。
- 发送前先保存尝试记录，再调用 OneBot；失败、超时或重启留下的未确认尝试不会自动重发，以免重复催缴。页面会显示原因；核对群里确实未收到后，可点「确认群内未收到，重试本月通知」。已成功月份不能通过此按钮重发。
- 本月去重状态保存在 `data/webui_fee_state.json`，迁移时一并保留。

## 网页功能

- **刷新间隔自定义**：1–10080 分钟，支持 2.5 等小数，也可选 1、5、15、30、60 分钟预设。运行中保存即重新计时，无需重启；每次采集完成后等待设定分钟数再进行下一次采集。
- **数据范围**：回溯 1–3650 天；页面显示最近一次采集范围内最多 200 条记录。
- **监测启停**：启动后立即采集；停止后不再调度新任务。已开始的网络请求会收尾，已经提交的推送无法撤回。
- **状态展示**：采集数量、最近成功时间、下次采集倒计时、待推送数量和运行日志。页面每 4 秒刷新状态，与学校采集间隔相互独立。
- **群通知配置**：OneBot 地址、访问令牌、QQ 群号均可在网页保存；支持只读检查连接和 @全体权限。
- **查寝推送开关**：配置 OneBot 后开启右上开关并保存。之后启动的监测会 @全体推送新记录；手动采集始终不推送。第一次监测仅建立基线；已有基线且查寝推送未开启时，新记录保留待推送。
- **登录保护**：管理密码以 scrypt 哈希保存，Cookie 为 HttpOnly / SameSite=Strict；配置接口校验登录、CSRF 和来源。学校出现验证码、认证拒绝或限流时会停止监测，需要处理后手动启动。
- **凭据修改**：密码和 AppSecret 不回显；输入框留空保持原值，填写新值后保存即替换。

## 持久化与迁移

`compose.yaml` 挂载 `./data:/app/data`，保存配置、管理密码哈希、采集缓存、独立账号基线和日志。容器重建后保留数据；已开启的监测会在服务重启后恢复，验证码导致的停止状态也会保留。

学校密码、QQ AppSecret 和 OneBot 访问令牌为自动运行所需，**以明文保存在本机 `data/webui_config.json`**，不会出现在 API 返回、网页或镜像中；Linux 文件权限为 600。管理密码哈希不用于加密学校凭据。数据目录需由你自己保管，迁移时复制整个目录，勿公开上传。源代码 ZIP 不含此目录或已保存的凭据。

本机接手目录中的原始 34 条基线保持原样。WebUI 仅在学校账号与原始导出账号一致时导入它，后续写入该账号独立的 `webui_state_*.json`，换账号不会沿用他人的已读状态。

日志 `webui.log` 每个文件最大约 1 MB，保留 3 个备份；页面展示本次进程的最近 100 条事件。备份时请同时保留原始数据和账号基线。不要同时运行旧 CLI 同步程序与 WebUI。

忘记管理密码时，先停止容器，把 `data/webui_admin.json` 移至私人备份位置，再启动容器并在网页重新设置。此操作要求有本机文件访问权，账号配置不受影响。

## 日常命令

```powershell
docker compose ps
docker compose logs --tail 100 -f
docker compose stop
docker compose up -d
```

容器健康检查确认 HTTP 服务与调度线程存活；学校最近采集失败会显示在网页，服务健康不代表学校或 QQ 的网络链路均正常。

默认仅本机访问。若部署到远程服务器，建议保持端口绑定本机，使用 SSH 隧道：

```text
ssh -L 8787:127.0.0.1:8787 your-user@your-server
```

然后仍从自己电脑访问 `http://127.0.0.1:8787`。如自行改为局域网或域名访问，还需设置 `WEBUI_ALLOWED_HOSTS` 为允许的主机名，并为远程访问配置 HTTPS；管理 Cookie 默认用于本机 HTTP，不应直接把该服务公开暴露到互联网。

## 验证

本轮 Windows 已通过 94 项测试，包括电费解析、CAS 回调、手动/自动电量查询与原有查寝、网费提醒测试。旧版本的 68 项曾在 Linux Docker 通过；新增电量功能尚未在 Docker 部署或测试。

浏览器使用虚构记录验证了采集及启停操作，新增功能验证了 6 人每人 18.88 元实时合计 113.28 元、微信宿舍群转账预览、31 日计划与网费开关保存。Docker 镜像已实测构建并运行，容器健康检查通过。

```powershell
python -m unittest -v test_webui test_handover test_reminders test_electricity test_electricity_webui
```

`test_handover` 会核验接手目录的 34 条原始数据；源码交接包不含私人数据，该项自动跳过，其余测试正常运行。本次开发使用模拟 OneBot，没有进行真实 QQ 群推送或登录实际 QQ 账号；配置你自己的免费 OneBot 服务并通过权限检查后才能实际发送。此前学校实时采集通过的结果见 `verification-live.json`。

原命令行操作说明归档在 [README-CLI.md](README-CLI.md)，原始交接说明见 [HANDOVER.md](HANDOVER.md)。
